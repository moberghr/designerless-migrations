## Purpose
Single-file EF Core migrations: `dotnet ef migrations add` writes one file with `[DbContext]` and `[Migration]` on the class and no `.Designer.cs`, by referencing a package and adding one options call. Evidence: `README.md` (intro, Quick start).

## Users
.NET teams using EF Core 10 with PostgreSQL whose Designer files dominate build time and diffs. Both forward-only projects (no `Down()` after review) and projects that keep `Down()` are supported. Evidence: `README.md` (What you get), `src/Moberg.EntityFrameworkCore.DesignerlessMigrations/MigrationConventionOptions.cs` (`AllowDown`).

## Key flows
- Add a migration: `DesignerlessMigrationsScaffolder.ScaffoldMigration` / `Save` in `src/Moberg.EntityFrameworkCore.DesignerlessMigrations/DesignerlessMigrationsScaffolder.cs`.
- Remove a migration with the snapshot restored from git: `RemoveMigration` and `src/Moberg.EntityFrameworkCore.DesignerlessMigrations/Scaffolding/GitModelSnapshot.cs`.
- Apply migrations with correct SQL: `src/Moberg.EntityFrameworkCore.DesignerlessMigrations.Npgsql/DesignerlessNpgsqlMigrationsSqlGenerator.cs`.
- Gate PRs with a convention test: `src/Moberg.EntityFrameworkCore.DesignerlessMigrations/MigrationConventions.cs`.
- Convert an existing repo once: `tools/convert-to-designerless.cs`.
