# Migrations code and data (§5)

## §5.1 Editing EF-generated code
- [ENFORCED] Keep the file's BOM and line endings exactly as EF wrote them; detect the newline from the input. Evidence: `src/Moberg.EntityFrameworkCore.DesignerlessMigrations/Scaffolding/MigrationCodeRewriter.cs`, `tools/convert-to-designerless.cs`.
- [ENFORCED] Usings are sorted System-first, then ordinal, and never duplicated.
- [ENFORCED] Fail loudly when the scaffolded shape is unexpected: exactly one `public partial class X : Migration`, a contiguous using block. Never guess a position — because a silently misplaced attribute makes EF skip the migration.
- Attributes go on their own lines directly above the class, after any doc comment, as `[DbContext(typeof(Ctx))]` then `[Migration("<id>")]`.

## §5.2 Restoring the snapshot
- [ENFORCED] `migrations remove` writes the snapshot bytes exactly as `git cat-file --filters` returns them; never decode and re-encode — because that changes the BOM or line endings and leaves the file modified after a remove. Evidence: `src/Moberg.EntityFrameworkCore.DesignerlessMigrations/Scaffolding/Git.cs` (`RunForBytes`).
- Run git through `ProcessStartInfo.ArgumentList`, never a concatenated argument string — because file names come from the user's project.

## §5.3 SQL generation without a model
- [ENFORCED] `DesignerlessNpgsqlMigrationsSqlGenerator` overrides only `IsOldColumnSupported => true` and `HasLegacyRenameOperations => false`. A nullability-only `AlterColumn` must not emit `TYPE`. Evidence: `tests/Moberg.EntityFrameworkCore.DesignerlessMigrations.Npgsql.Tests/DesignerlessNpgsqlMigrationsSqlGeneratorTests.cs`.
- [ENFORCED] Data operations need explicit types: `InsertData` `columnTypes:`, `UpdateData` both `columnTypes:` and `keyColumnTypes:`, `DeleteData` `keyColumnTypes:` — because without a model EF throws when the migration is applied. Evidence: `samples/NpgsqlSample/Migrations/20261116122522_SeedCurrencies.cs`, `MigrationConventions.FindDataOperationsWithoutColumnTypes`.

## §5.4 Sample migrations
- [ENFORCED] Sample migrations are generated by the real `dotnet ef` through the packed package (never hand-written from scratch), then made forward-only by deleting `Down()` entirely. Evidence: `samples/NpgsqlSample/Migrations/`.
- When the sample model changes, regenerate the migration and snapshot with `dotnet ef` so `HasPendingModelChanges()` stays false (`samples/NpgsqlSample.Tests/MigrationConventionsTests.cs`).
- Migration files match `^\d{14}_\w+\.cs$`; Designer and snapshot files never do. Evidence: `MigrationFileGuard.IsMigrationFile`.
